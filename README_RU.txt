ОПЕРАТИВНЫЙ ЖУРНАЛ ГОРНОГО ДИСПЕТЧЕРА — EXE 134

Основа: неизменённый рабочий пакет версии 133; единственная функциональная правка версии 134 — повторное подключение изображений погрузчиков после загрузки JSON/резервной копии.
Механизм обновления: сохранён из пакета версии 126 (latest.json, выбор папки, установка HTML-обновления, откат).

СБОРКА УСТАНОВЩИКА
1. Загрузите содержимое папки journal-exe-134 в корень отдельного репозитория GitHub либо замените файлы в существующем репозитории.
2. В GitHub Actions запустите workflow “Build Journal EXE 134” (или отправьте изменения в main).
3. Скачайте artifact Journal-134-Setup. Внутри должен быть Journal-134-Setup.exe.

JSON ДАННЫХ
При первом подключении выбирается уже существующий JSON. Создание нового JSON через основную кнопку сохранения отключено. Путь сохраняется в настройках приложения. Если файл отсутствует, его нужно выбрать повторно.


ВНУТРЕННЕЕ ХРАНИЛИЩЕ EXE 134
Приложение хранит рабочую базу отдельным файлом journal-local-state.json в пользовательской папке данных Electron (userData), а не полагается только на localStorage. Снимок включает данные всех вкладок, пользователей, лицензии, настройки и изображения/фон. При запуске эта база восстанавливается до запуска основного кода журнала. Данные из версии 129 в локальном профиле при первом запуске 134 мигрируются в новое хранилище.

ПРАВИЛА СОХРАНЕНИЯ JSON
Если содержимое выбранного JSON совпадает с последней принятой версией, актуальная база спокойно записывается поверх файла. Если хеш JSON изменился извне, приложение показывает сведения о создании и последнем сохранении (если они есть в файле) и предлагает загрузить данные из JSON, сохранить базу приложения поверх JSON или отменить действие. Загрузка JSON полностью заменяет текущую рабочую базу и сохраняет её во внутреннем хранилище.

ОБНОВЛЕНИЯ
В приложении выберите папку, где находятся latest.json и HTML-файл обновления. В latest.json укажите versionCode больше установленного и file с точным именем HTML-файла. Обновление заменяет runtime HTML; предыдущая версия сохраняется для отката.

ВАЖНО
Пакет подготовлен для Windows x64 с Electron 22.3.27 (последняя ветка Electron с поддержкой Windows 7). Фактический установщик создаётся GitHub Actions. До выполнения Actions и запуска на Windows 7 нельзя считать EXE проверенным.


ИСПРАВЛЕНИЕ ВЕРСИИ 133
Резервное копирование в «Базе ввода данных» использует тот же сбор данных, формат JSON и обработчик загрузки, что и основная кнопка «Сохранить». Кнопка сохранения резервной копии открывает выбор пути и имени файла; кнопка загрузки — выбор JSON-файла. Основной путь сохранения не переключается.


Версия 133: резервное копирование в разделе «База ввода данных» в EXE использует тот же сбор данных и формат JSON, что и основная кнопка «Сохранить». Сохранение резервной копии открывает выбор пути и имени файла; загрузка открывает выбор JSON и применяет данные через тот же обработчик, что и обычная загрузка JSON. Основной путь сохранения не переключается. Остальные функции версии 131 сохранены.


ИСПРАВЛЕНИЕ ВЕРСИИ 133
Версия 133 основана на рабочей версии 132. Исправлена проверка конфликтов localStorage во время загрузки резервной копии: контролируемый импорт не считается изменением из другой вкладки, после импорта синхронизируются контрольные снимки и сбрасывается ложный флаг конфликта. После успешной загрузки резервной копии внутреннее хранилище сохраняется, а предупреждение beforeunload о несохранённом JSON не блокирует закрытие приложения. Остальные функции версии 132 сохранены.


ИЗМЕНЕНИЕ ВЕРСИИ 134
Версия 134 создана на основе рабочего пакета 133. Единственное функциональное изменение: после загрузки JSON или резервной копии изображения погрузчиков повторно подключаются к карточкам техники без перезапуска приложения. Существующий механизм обычного сохранения и резервного копирования продолжает включать фон окна входа и отдельные изображения погрузчиков в поле media; изображения остальных видов техники сохраняются в основной базе данных (imageData). Остальные функции, интерфейс и логика версии 133 не изменялись.
