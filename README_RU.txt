ОПЕРАТИВНЫЙ ЖУРНАЛ ГОРНОГО ДИСПЕТЧЕРА — EXE 139

Основа: Journal_EXE_138_GitHub_Package. В версии 139 изменена только компоновка и фильтрация периода в блоке «Вывезено по направлениям со всех блоков» во вкладке «Объёмы блоков»: добавлено поле «Считать по дату» рядом с фильтром карьера и полем «Считать с даты». Остальная логика сохранена. Остальные вкладки и их логика сохранены.
Механизм обновления: сохранён из пакета версии 126 (latest.json, выбор папки, установка HTML-обновления, откат).

СБОРКА УСТАНОВЩИКА
1. Распакуйте архив и загрузите его содержимое в корень отдельного репозитория GitHub либо замените файлы в существующем репозитории.
2. В GitHub Actions запустите workflow “Build Journal EXE 139” (или отправьте изменения в main).
3. Скачайте artifact Journal-139-Setup. Внутри должен быть Journal-139-Setup.exe.

JSON ДАННЫХ
При первом подключении выбирается уже существующий JSON. Создание нового JSON через основную кнопку сохранения отключено. Путь сохраняется в настройках приложения. Если файл отсутствует, его нужно выбрать повторно.


ВНУТРЕННЕЕ ХРАНИЛИЩЕ EXE 139
Приложение хранит рабочую базу отдельным файлом journal-local-state.json в пользовательской папке данных Electron (userData), а не полагается только на localStorage. Снимок включает данные всех вкладок, пользователей, лицензии, настройки и изображения/фон. При запуске эта база восстанавливается до запуска основного кода журнала. Данные из версии 129 в локальном профиле при первом запуске версии 135 мигрируются в новое хранилище.

ПРАВИЛА СОХРАНЕНИЯ JSON
Если содержимое выбранного JSON совпадает с последней принятой версией, актуальная база спокойно записывается поверх файла. Если хеш JSON изменился извне, приложение показывает сведения о создании и последнем сохранении (если они есть в файле) и предлагает загрузить данные из JSON, сохранить базу приложения поверх JSON или отменить действие. Загрузка JSON полностью заменяет текущую рабочую базу и сохраняет её во внутреннем хранилище.

ОБНОВЛЕНИЯ
В приложении выберите папку, где находятся latest.json и HTML-файл обновления. В latest.json укажите versionCode больше установленного и file с точным именем HTML-файла. Обновление заменяет runtime HTML; предыдущая версия сохраняется для отката.

ВАЖНО
Пакет подготовлен для Windows x64 с Electron 22.3.27 (последняя ветка Electron с поддержкой Windows 7). Фактический установщик создаётся GitHub Actions. До выполнения Actions и запуска на Windows 7 нельзя считать EXE проверенным.

Версия 133: резервное копирование в разделе «База ввода данных» в EXE использует тот же сбор данных и формат JSON, что и основная кнопка «Сохранить». Сохранение резервной копии открывает выбор пути и имени файла; загрузка открывает выбор JSON и применяет данные через тот же обработчик, что и обычная загрузка JSON. ИСПРАВЛЕНИЕ ВЕРСИИ 133
Версия 133 основана на рабочей версии 132. Исправлена проверка конфликтов localStorage во время загрузки резервной копии: контролируемый импорт не считается изменением из другой вкладки, после импорта синхронизируются контрольные снимки и сбрасывается ложный флаг конфликта. После успешной загрузки резервной копии внутреннее хранилище сохраняется, а предупреждение beforeunload о несохранённом JSON не блокирует закрытие приложения. Остальные функции версии 132 сохранены.


ИЗМЕНЕНИЕ ВЕРСИИ 138
Версия 138 создана на основе рабочего пакета Journal_EXE_136_GitHub_Package. Во вкладке «БВР» сохранённые записи хранят исторические названия буровых станков, карьеров и блоков. Удаление или переименование объектов в базе данных не удаляет и не переписывает уже сохранённые записи БВР. При редактировании старой записи допускается повторное сохранение с её исходными данными, даже если соответствующий объект уже отсутствует в актуальной базе. Для новых записей используются объекты из текущей базы. Другие вкладки, расчёты, JSON, лицензирование и функции EXE 136 не изменялись.


ИЗМЕНЕНИЕ ВЕРСИИ 139
Версия 139 создана на основе рабочего пакета Journal_EXE_138_GitHub_Package. Во вкладке «Объёмы блоков» в сводке вывезенных объёмов добавлено поле «Считать по дату» рядом с фильтром карьера и полем «Считать с даты». Расчёт учитывает выбранный карьер и обе даты периода. Остальные вкладки, расчёты, JSON, лицензирование и функции EXE 138 не изменялись.
